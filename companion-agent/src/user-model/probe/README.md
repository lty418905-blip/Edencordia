這是未接線的探針核心開發快照（規劃與提問流程），沒有產品呼叫端。
核心使用文字分段與內容家族，不含等級、資訊分數、老化天數或內建題庫。
登記表由呼叫端每次提供；內容尚未整理，目前沒有任何可投入的登記表列，舊 26 題只在測試夾具，授權一律未核對。
所有時刻、當地日週鍵、種子與候選 ID 由呼叫端給；閘門判定不了就不問。
規劃在一次 owned-data 快照上完成，再提交五個欄位；普通物件先檢查可寫性，選擇性失敗的 Proxy 不保證原子提交。
資料只來自使用者與本 agent 的聊天及明確授權的 PC 範圍；本核心不收集、不儲存、不呼叫模型。
提問流程已以純函式交付（見文末「提問流程」一節），仍未接線，只由測試執行；輸入投影、儲存與宿主接線尚未交付。
學習開關關閉時整個停止（不提探針，呼叫端也停止收集）。苦惱時窗與通用情境（剛爭執過的同一天、使用者想自己待著、深夜、剛短答之後）只停止主動提出探針；被動的採樣與側寫的收集不因這些時刻而停止，這些時刻收到的資料由呼叫端帶上情境標記。
使用者的非負面情緒不擋主動探針（使用者 2026-10-10）：他表達親近、開心或思念時，她仍然可以問。苦惱時窗只指負面的情緒狀態；登錄表的禁問情境裡沒有「他剛表達思念」這一項。
她剛說了很長一段、剛自我揭露、剛沉默過，以及他剛表達思念，都不是禁問情境（使用者 2026-10-10）：呼叫端可以回報這些情境，選題不因它們關閉任何面向；問句要接得上當下的聊天語境、不能像問卷，由寫問句的那一步負責。登錄列能宣告的禁問情境只剩「他在反芻」與「他在趕時間」。被動的收集與評估除了使用者在工作區後台關閉學習之外始終開啟。
被直接問起時怎麼回(「你為什麼問這個」「你是不是在分析我」「你記了我什麼」「別再記了」)由產品負責人親自寫, 位置在 owner-disclosure.ts 的 OWNER_DISCLOSURE_REPLIES; 現在每一格都是空的, 空的時候不往她的回覆加任何東西, 程式與模型都不得代填.

## 提問流程（flow.ts、flow-gates.ts、flow-input.ts；純函式，未接線）

一個探針的一生：待提出（在 pending 裡）→ 已提出（flow.offer）→ 已送達、等回答（awaitingAnswer）→ 結果（answered、evasive、unanswered）。四個對外入口各對應一個事件，每個入口只快照一次輸入、不改呼叫端的任何物件、成功時回傳全新的狀態，失敗時狀態為 null 並帶原因碼；沒有時鐘、亂數、儲存與文字，時刻、日週鍵、識別碼與擲骰值都由呼叫端給。四個入口對狀態做同一套檢查，一個入口接受的狀態其餘三個也接受：流程自己存的成員（帳、等待紀錄、候選的成員、措辭指紋）缺漏或損壞一律是 invalid_input；狀態裡任何位置出現 undefined（共用快照會保留陣列裡的 undefined）也拒絕，所以回傳的狀態裡沒有 undefined。

- receiveUserTurn：一則使用者訊息被接受之後呼叫。送達後的第一則使用者訊息決定結果（等待 24 小時；逾時、時鐘倒退或沒有判定都記 unanswered）；結果記進總計、面向與組別；連續兩次敷衍讓該面向停 7 天（只影響她多久再問，不是對他的理解）；結算之後接下來 8 到 20 則使用者訊息不提探針；他明說不談的面向的候選立刻移除，那一回合不提任何探針。同一回合重複呼叫不重複生效。這個入口沒有苦惱、情境或情緒的輸入：被動收集不因任何時刻而停，每一筆結算都帶「被問出來」的標記（elicitation 恆為 probe，逾時也帶），永遠不記成自發。
- offerProbe：開口前的檢查。整次的閘門依序是：學習關閉、尚未收到這一回合、苦惱時窗、通用情境、這一回合的拒絕、這一回合剛結算、已有探針在等回答、追問預算（不知道就不問）、結算後的停頓、日與週的送達上限、沒有合格候選、擲骰。苦惱時窗與通用情境只停主動探針，狀態完全不變；提示情境（他剛表達思念、她剛說了很長一段、她剛自我揭露、她剛沉默過）不關任何閘門。候選依 pending 的次序逐一檢查（到期、剛提出過、沒有登記列、單一面向的閘門以目前的檢視再查一次、每週研究上限、面向冷卻、最小間隔、情境與時段），第一個全部通過的被提出。每個使用者回合只擲一次骰，重生成不會再擲。提出只改三處（候選的 lastOfferedAtMs、flow.offer、stats.offers），什麼都不登記；輸出只有識別碼、封閉清單的值與數字。
- settleOffer：宿主接受了她那則訊息之後回報。used 或 rewritten 才登記送達（移出 pending、開始等回答、面向與組別與日週計數、措辭指紋每面向留十筆、待複核面向的研究帳）；已經問出口的就是事實，登記時不再查任何閘門。skipped 只關掉這次提出，候選留著，15 分鐘內不再提。
- withdrawDelivery：帶著問題的那則訊息不再有效時呼叫。只結束等待；送達時記的計數與額度都不退回。

學習開關關閉時三個入口都把在途的東西清掉（pending、已提出、等回答，等回答的那一個不結算），但不清她學到與記下的任何東西；清除只能由使用者在後臺手動操作，這裡沒有那樣的轉換。聊天裡說的話不會關掉學習：拒絕只讓這一回合歸零並移除被點名面向的候選；「哪個面向被明說不談」這個事實不存在流程裡，由之後的儲存那一包保存，經面向檢視的 declined 回來。

flow-gates.ts 提供設定與期限：DEFAULT_FLOW_CONFIG（每個數值都是暫定的預設，等校準）；deriveFacetGates 由事實的日期導出單一面向的閘門（反饋當天與其後 13 天不問，第 14 天起可問；糾正或刪除當天與其後 29 天不問，第 30 天起可問；明說不談沒有期限）；researchGateOf 給出每週研究探針的上限與本週已送達數；distressWindowHolds 只算苦惱後 24 小時的時間；elicitationFor 回答某個面向在這則訊息裡的證據是否被探針問出，從不回答「自發」。day-keys.ts 新增日鍵加天數（addDays）。

這一包沒有做的：同一回合的追問；待複核標記 30 天與 90 天的降級；每個分類各自的週上限與每題各自的機率；寫問句與挑提示（提出只給提示的索引，文字留在登記表）；任何儲存與接線。規劃時的每週輪換份數不在提出時重查。
