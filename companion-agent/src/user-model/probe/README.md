這是未接線的探針規劃核心開發快照，沒有產品呼叫端。
核心使用文字分段與內容家族，不含等級、資訊分數、老化天數或內建題庫。
登記表由呼叫端每次提供；內容尚未整理，目前沒有任何可投入的登記表列，舊 26 題只在測試夾具，授權一律未核對。
所有時刻、當地日週鍵、種子與候選 ID 由呼叫端給；閘門判定不了就不問。
規劃在一次 owned-data 快照上完成，再提交五個欄位；普通物件先檢查可寫性，選擇性失敗的 Proxy 不保證原子提交。
資料只來自使用者與本 agent 的聊天及明確授權的 PC 範圍；本核心不收集、不儲存、不呼叫模型。
後續提問流程、輸入投影與宿主接線尚未交付。
學習開關關閉時整個停止（不提探針，呼叫端也停止收集）。苦惱時窗與通用情境（剛爭執過的同一天、使用者想自己待著、深夜、剛短答之後）只停止主動提出探針；被動的採樣與側寫的收集不因這些時刻而停止，這些時刻收到的資料由呼叫端帶上情境標記。
使用者的非負面情緒不擋主動探針（使用者 2026-10-10）：他表達親近、開心或思念時，她仍然可以問。苦惱時窗只指負面的情緒狀態；登錄表的禁問情境裡沒有「他剛表達思念」這一項。
她剛說了很長一段、剛自我揭露、剛沉默過，以及他剛表達思念，都不是禁問情境（使用者 2026-10-10）：呼叫端可以回報這些情境，選題不因它們關閉任何面向；問句要接得上當下的聊天語境、不能像問卷，由寫問句的那一步負責。登錄列能宣告的禁問情境只剩「他在反芻」與「他在趕時間」。被動的收集與評估除了使用者在工作區後台關閉學習之外始終開啟。
被直接問起時怎麼回(「你為什麼問這個」「你是不是在分析我」「你記了我什麼」「別再記了」)由產品負責人親自寫, 位置在 owner-disclosure.ts 的 OWNER_DISCLOSURE_REPLIES; 現在每一格都是空的, 空的時候不往她的回覆加任何東西, 程式與模型都不得代填.
